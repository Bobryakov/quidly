# Quidly

Личный учёт финансов. Работает в браузере и ставится на телефон как приложение.
Все данные хранятся только на устройстве — без серверов и регистрации.

**Адрес:** https://bobryakov.github.io/quidly/

## Как поставить на телефон

- **Android (Chrome):** откройте адрес → меню ⋮ → «Установить приложение» (или «Добавить на главный экран»).
- **iPhone (Safari):** откройте адрес → «Поделиться» → «На экран «Домой»».

После установки Quidly открывается как обычное приложение и работает без интернета. Когда выходит новая версия, появляется плашка «Вышла новая версия → Обновить».

## Где хранятся данные и как их не потерять

- Всё хранится только в памяти телефона, в браузере. Серверов и регистрации нет — никто, кроме вас, данных не видит.
- Поэтому раз в неделю сохраняйте **резервную копию** («Настройки → Резервная копия») и переносите файл в облако или на компьютер. Quidly сам напомнит.
- На новом телефоне: установите Quidly → на первом экране «Есть резервная копия? Восстановить».
- Каждый человек ведёт свой учёт на своём телефоне: общего семейного бюджета нет.

## Что уже есть

**Этап 9 — доводка**
- Новые категории расходов «🏦 Кредиты» и «🧾 ЖКХ» (у тех, кто уже пользуется, появились при обновлении).
- Кнопка «+» прячется, пока листаете список вниз, и есть только на основных экранах — не закрывает суммы и кнопки.
- Свои окна «Удалить …?» вместо серых системных окон браузера.
- Первый экран: тип счёта — кнопками, название не обрезается. В меню подсвечены «Настройки», когда открыты бюджеты, подписки или импорт.


**Этап 8 — защита, экспорт, резервная копия**
- PIN-код из 4 цифр (хранится только хеш PBKDF2 с солью), вход по отпечатку или лицу (WebAuthn), автоблокировка: сразу / 1 / 5 / 15 минут.
- После 5 ошибок подряд — пауза (30 секунд, потом дольше). «Забыли PIN?» — сброс только вместе с данными, со словом «УДАЛИТЬ».
- PIN — замок экрана, а не шифрование: об этом сказано в настройках.
- Экспорт операций за период в Excel (.xlsx) и CSV (для русского Excel: «;», запятая в суммах).
- Резервная копия всех данных в JSON-файл с версией базы; по желанию — с паролем (AES-GCM). Восстановление: проверка файла → что в копии → подтверждение замены. Старые копии дополняются до новой версии.
- Восстановить можно и на новом телефоне — прямо со знакомства.
- Напоминание о копии на главной раз в неделю; в настройках — дата последней копии.

**Этап 7 — импорт выписок (Сбер + CSV/Excel)**
- «Настройки → Импорт выписки»: PDF Сбера («Выписка по платёжному счёту») и любые CSV/Excel (колонки выбираются).
- Сверка с итогами выписки Сбера; предпросмотр с галочками; категории подбираются сами и запоминаются правилами.
- Переводы на свои счета и наличные, комиссия отдельно, взаимозачёт возвратов, защита от дублей, связь с подписками.
- «Выровнять остаток по выписке» — баланс счёта совпадает с банком.
- Файлы читаются только на устройстве. Реальные выписки для разработки — в `samples/`, на GitHub не попадают.

**Этап 6 — аналитика**
- Экран «Аналитика»: период — месяц, 3 месяца или год.
- Траты по категориям: кольцевая диаграмма и список с процентами; тап — операции категории.
- Доходы и расходы за 6 месяцев; честное сравнение текущего месяца с теми же днями прошлого.
- Прогноз: «При таком темпе потратишь X ₽» и «Можно тратить Y ₽ в день» (с учётом общего бюджета).
- Календарь-тепловая карта трат (неделя с понедельника); тап по дню — операции дня.
- «Операции»: фильтры по счёту и категории (в дополнение к месяцу, типу и поиску).

**Этап 5 — копилки**
- Экран «Цели»: копилки с целевой суммой, необязательным сроком, эмодзи и цветом; прогресс в процентах.
- Пополнить / снять (не больше, чем лежит), история движений, «Отменить».
- Подсказка «Чтобы успеть к сроку, откладывай X ₽ в месяц».
- Конфетти, когда цель достигнута 🎉.
- Копилки виртуальные: деньги остаются на счетах. На главной — «в копилках X ₽ · свободно Y ₽».
- В «Итогах месяца» — «🐷 В копилку»: остаток категории пополняет выбранную копилку.

**Этап 4 — подписки**
- Список подписок: сумма, как часто (неделя / месяц / квартал / год), дата следующего списания, счёт, категория; пауза и удаление.
- Сумма всех подписок в пересчёте на месяц и на год.
- На главной — плашка «Скоро спишется» (за 1 / 3 / 7 дней) с кнопкой «Проведено»: трата записывается одним тапом, дата сдвигается. Есть «Отменить».
- Пропущенные списания: «Списалось 10.10.2026?» — «Проведено» или «Пропустить», по каждому.

**Этап 3 — бюджеты**
- Лимит на месяц для любой расходной категории и общий бюджет (по умолчанию — сумма категорий, можно вписать свой).
- Цветные полоски: зелёная < 80%, жёлтая 80–100%, красная > 100%.
- Предупреждение в плашке после траты: «потрачено 85% лимита», «лимит превышен на …».
- Перенос остатка на следующий месяц («Лимит 10 000 ₽ + 1 200 ₽ с прошлого месяца»), можно выключить для категории.
- В начале месяца — карточка «Итоги месяца»: перенести, покрыть перерасход другой категории или обнулить. Без решения — после 7-го числа остатки переносятся сами.
- Настройка «Переносить перерасход».

**Этап 2 — счета, категории, быстрый ввод**
- Первый запуск: знакомство «Сколько у вас сейчас денег?» — счета с текущими остатками.
- Быстрый ввод: «+» → сумма на крупной клавиатуре → тап по категории — готово. Частые категории — первыми.
- Расход, доход и перевод между своими счетами (перевод не считается ни расходом, ни доходом).
- Дата, счёт (по умолчанию — последний использованный) и комментарий — по желанию.
- Правка и удаление операции, после удаления — «Отменить».
- Экран «Операции»: по дням, по месяцам, фильтр по типу, поиск.
- Настройки → Счета (баланс, архив) и Категории (добавить, переименовать, эмодзи, цвет, объединить).
- Данные хранятся в базе браузера на устройстве (IndexedDB).

**Этап 1 — каркас**
- 5 экранов (Главная, Операции, Аналитика, Цели, Настройки) и нижнее меню.
- Светлая, тёмная и «как в системе» тема.
- Установка на телефон (PWA) и работа без интернета.

- Автопубликация на GitHub Pages при каждой отправке в ветку `main` (с прогоном тестов).

## Команды

| Команда | Что делает |
|---|---|
| `npm install` | Ставит пакеты (один раз и после обновлений). |
| `npm run dev` | Запускает приложение на ноутбуке: http://localhost:5173/quidly/ |
| `npm test` | Прогоняет тесты. |
| `npm run build` | Собирает версию для публикации в папку `dist`. |
| `npm run preview` | Показывает собранную версию: http://localhost:4173/quidly/ |

## Стек

React + TypeScript + Vite, Tailwind, Dexie (база на устройстве, схема версии 6), vite-plugin-pwa, Framer Motion, React Router, Recharts, Vitest.
Графики — Recharts. Импорт: pdf.js (PDF), PapaParse (CSV), SheetJS (Excel; ставится с официального сайта cdn.sheetjs.com).

## Для разработчика

- Схема базы — `src/db/db.ts`. Уже выпущенные версии схемы **не менять**: только добавлять `version(N+1)` с миграцией.
- Все изменения данных — через `src/db/repo.ts` (там проверки).
- Расчёты (`src/lib`, в т.ч. бюджет — `src/lib/budget.ts`) и работа с базой покрыты тестами (`*.test.ts`).
- Схема базы сейчас — версия 6 (этап 3 добавил `budgets` и `closings`, этап 4 — `subscriptions`, этап 5 — `goals` и `goalMoves`, этап 7 — `importRules` и метку `importKey`, этап 9 — категории «Кредиты» и «ЖКХ»); переходы со старых версий проверяются тестами.
- Новые стартовые категории добавляются только в конец списка в `src/db/seed.ts` (иначе сдвинутся их id), место в списке — `EXPENSE_ORDER`.
