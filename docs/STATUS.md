## Принятые решения
- Название: Quidly.
- Копилки ведутся отдельно от счетов.
- Геймификация: серия дней + 5 бейджей (см. SPEC, раздел 10).
- Забытый PIN: сброс только с удалением данных, затем восстановление из бэкапа.
- Перенос остатка бюджета включён + карточка «Итоги месяца» (SPEC, раздел 5.1).
- Быстрый ввод: счёт по умолчанию — последний использованный (17.11.2026).
- Первый запуск: экран знакомства «Сколько у вас сейчас денег?» с готовыми «Карта» и «Наличные» (17.11.2026).
- Бюджеты: месяц — календарный, с 1-го числа; общий лимит = сумма категорий по умолчанию, можно вписать свой; «Отправить в копилку» в «Итогах месяца» — на этапе 5 (17.11.2026).
- Подписки: напоминать за 3 дня (можно 1 / 3 / 7); пропущенные списания — спрашивать про каждое по очереди (17.11.2026).
- Копилки: на главной «в копилках X · свободно Y»; срок цели необязательный (17.11.2026).
- Этап 8 (21.11.2026): телефон владельца — **Android**; вход по отпечатку/лицу — да, сразу; автоблокировка по умолчанию — через 1 минуту (можно сразу / 5 / 15 мин); пароль на резервную копию — по желанию.
- Импорт (17.11.2026): переводы на свои счета — предлагать как перевод; возврат + покупка в одной выписке — взаимозачёт (обе не импортируются); «похоже на ручную запись» — помечать и не импортировать (галочка снята).

### Технические решения
- Адреса экранов через `#` (`/quidly/#/settings`) — чтобы GitHub Pages не выдавал «страница не найдена» при обновлении.
- Обновление приложения — только по кнопке «Обновить» на плашке, без автоперезагрузки посреди ввода.
- Выбор темы хранится в localStorage (настройка интерфейса). Финансовые данные — в IndexedDB через Dexie (`src/db/db.ts`, схема **версии 5**).
- Схема БД v1: `accounts`, `categories`, `transactions`, `meta`. v2 (этап 3): + `budgets` (лимит с месяца `fromMonth`, `limit: null` — снят; общий — `categoryId = 'total'`), + `closings` (итоги месяца: решения, переносы, покрытия). У категории необязательное поле `budgetRollover` (нет = переносить). v3 (этап 4): + `subscriptions` (nextDate, anchorDay — «число месяца» для 31-го, paused), у операций необязательное `subscriptionId` + индекс. v4 (этап 5): + `goals` (target, deadline?, achievedAt), + `goalMoves` (amount со знаком, source manual|closing). В `CloseAction` добавлен вариант `goal`, в `MonthClosing` — `toGoals`. v5 (этап 7): + `importRules` (pattern → categoryId), у операций необязательное `importKey` + индекс. Переходы со всех прошлых версий (v1…v4 → v5) покрыты тестами. id — UUID-строки. Даты операций — строка `ГГГГ-ММ-ДД` по местному времени. Суммы — копейки, всегда > 0; знак задаёт тип (expense / income / transfer).
- Стартовые категории имеют постоянные id `seed-expense-1…12`, `seed-income-1…4`.
- Все изменения данных — через `src/db/repo.ts` (проверки: сумма > 0, категория подходит к типу, перевод не на тот же счёт и т. п.).
- Объединение категорий (`mergeCategories`) переносит операции, бюджеты (если у получателя нет своего), подписки и правила импорта; удаление пустой категории удаляет её правила.
- Импорт: `src/import/` — `sber.ts` (PDF Сбера по координатам строк), `pdfText.ts` (pdf.js, грузится только при импорте), `generic.ts` (CSV через PapaParse, Excel через SheetJS 0.20.3 с официального CDN — в npm-каталоге старая 0.18.5 с уязвимостью), `categorize.ts`, `plan.ts` (переводы, возвраты, дубли, подписки, баланс после импорта). Запись — `applyImport` в `repo.ts` одной транзакцией. Экран — `ImportPage.tsx` (lazy).
- `src/import/sber.real.test.ts` проверяет настоящие PDF из `samples/`, если они есть на компьютере (на GitHub пропускается).
- Формат Сбера (по реальной выписке): см. SPEC 4.2. Валютных операций в примере не было — колонка «Сумма в валюте операции» не проверена.
- Подписки: расчёты — `src/lib/subscriptions.ts`; «Проведено» / «Пропустить» / отмена — `markSubscriptionPaid` / `skipSubscriptionCharge` / `undoSubscriptionCharge` в `repo.ts`. Сопоставление с импортированными операциями — на этапе 7 (по `subscriptionId`).
- Копилки: расчёты — `src/lib/goals.ts`; пополнение/снятие — `addGoalMove` (не даёт уйти в минус, ставит `achievedAt` при первом достижении), отмена — `deleteGoalMove`. Конфетти — `celebrate()` в `src/lib/store.ts` + `Confetti.tsx`.
- `closeBudgetMonth` выполняется одной транзакцией: записывает итоги и пополняет копилки; если выбранную копилку удалили — остаток переносится.
- Аналитика: расчёты — `src/lib/analytics.ts`; экран `src/pages/AnalyticsPage.tsx` загружается отдельно (lazy), чтобы тяжёлая библиотека графиков не замедляла запуск. Графики — Recharts (кольцо и столбики), календарь — своя сетка.
- Фильтры «Операций» — в адресе экрана: `?month=&type=&account=&category=&day=&from=&to=&q=`. Фильтр по счёту показывает и переводы на этот счёт.
- Защита (этап 8): `src/lib/security/` — `pin.ts` (PBKDF2-SHA-256, 300 000 повторений, соль 16 байт; пауза после 5/10/15 ошибок: 30 с / 5 мин / 15 мин), `biometric.ts` (WebAuthn: ключ создаётся на телефоне, мы храним открытый ключ и сами проверяем подпись, флаги «присутствие + подтверждение личности», challenge и origin), `lockState.ts` (состояние замка и автоблокировка по `visibilitychange`; «Сразу» закрывает ещё в фоне). Запись — `src/db/securityRepo.ts`. Замок — `LockGate` (в `App`, не в `AppRoutes`, поэтому старые тесты экранов его не видят) и `LockScreen`. Пока приложение ни разу не открыли PIN-ом, экраны с данными не рисуются; при повторной блокировке экраны остаются под замком.
- Настройки защиты лежат в `meta` (`pin`, `pinFails`, `lockTimeout`, `biometric`, `lastBackupAt`, `backupSnoozeUntil`) — схема базы не менялась (v5). Эти ключи — `DEVICE_META`: в копию не попадают и при восстановлении не меняются.
- «Забыли PIN?» — `wipeAllData` (удаляет базу) и перезапуск; на знакомстве есть «Восстановить из копии».
- Резервная копия: `src/lib/backup.ts` — JSON `{app:'quidly', kind:'backup', format:1, schemaVersion, createdAt, checksum, data}`; с паролем — вместо `data`/`checksum` поле `encrypted` (AES-GCM 256, ключ PBKDF2-SHA-256 600 000 повторений, соль 16 байт, iv 12 байт). Проверки: чужой файл, версия новее приложения, контрольная сумма SHA-256, смысл данных (ссылки операций на счета, повторы ключей и т. п.). Старые копии дополняются `migrateBackup` (все переходы v1→v5 только добавляли таблицы). Восстановление — `restoreBackupData` одной транзакцией: если сорвалось, данные остаются как были.
- Экспорт: `src/lib/export.ts` — CSV для русского Excel (`;`, запятая, метка UTF-8, текст, похожий на формулу, — с апострофом), Excel — настоящие даты (`dd.mm.yyyy`) и числа; экран `ExportPage` lazy (SheetJS).
- Скачивание файлов — `src/lib/fileSave.ts` (на Android — в «Загрузки»); «Поделиться» показывается, только если телефон умеет делиться таким файлом.
- `src/pages/PlaceholderPages.tsx` больше не используется (все разделы готовы) — удалить на этапе 9 (с согласия владельца).
- Предупреждение о бюджете после траты — общий помощник `withBudgetWarning` (`src/db/budgetWatch.ts`), используется и в быстром вводе, и в «Проведено».
- Расчёты бюджета — чистые функции в `src/lib/budget.ts`. Перенос в текущий месяц: из `closings` прошлого месяца, а если он не закрыт — предварительный по умолчанию. При запуске `autoCloseMonths` закрывает по умолчанию все месяцы старше прошлого и прошлый — с 8-го числа.
- Предупреждения 80% / превышение показываются в плашке после записи траты, один раз при переходе порога.
- Номер открытия панели «+» — счётчик, а не время (иначе два быстрых открытия могли совпасть и форма не очищалась).
- При старте приложение просит браузер о «постоянном хранилище» (`navigator.storage.persist`), чтобы данные не стирались при нехватке места.
- Публикация: GitHub Actions на каждую отправку в `main`; если тесты не прошли — публикации нет.
- `npm audit` (17.11.2026): 14 предупреждений (2 moderate — workbox → glob/minimatch; 12 high — свежее предупреждение про `picomatch`, все версии, через vite/vitest/vite-plugin-pwa). Всё это — инструменты сборки и тестов, в приложение не попадают (проверено поиском по `dist`). Recharts к ним отношения не имеет. `npm audit fix --force` не запускать — он откатывает vite-plugin-pwa и vitest. Перепроверить, когда выйдут исправленные версии.
- В новых Chrome `window.scrollTo` возвращает Promise — эффекты React писать с фигурными скобками, без неявного возврата.

- Выписки: реальные файлы — только в `samples/` на ноутбуке (в git не попадают). Для тестов парсеров — выдуманные файлы с тем же устройством (колонки, форматы дат и сумм, кодировка), в репозитории.
- Что известно о выгрузках (17.11.2026, по открытым источникам): Т-Банк — CSV / XLS / OFX в личном кабинете на сайте, в выгрузке есть MCC; Сбер — Excel/PDF через веб-версию (возможно, только PDF); Альфа — PDF/Excel в Альфа-Онлайн. Проверить по реальным файлам.
