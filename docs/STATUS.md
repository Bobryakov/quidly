## Принятые решения
- Название: Quidly.
- Копилки ведутся отдельно от счетов.
- Геймификация: серия дней + 5 бейджей (см. SPEC, раздел 10).
- Забытый PIN: сброс только с удалением данных, затем восстановление из бэкапа.
- Перенос остатка бюджета включён + карточка «Итоги месяца» (SPEC, раздел 5.1).
- Быстрый ввод: счёт по умолчанию — последний использованный (17.11.2026).
- Первый запуск: экран знакомства «Сколько у вас сейчас денег?» с готовыми «Карта» и «Наличные» (17.11.2026).

### Технические решения
- Адреса экранов через `#` (`/quidly/#/settings`) — чтобы GitHub Pages не выдавал «страница не найдена» при обновлении.
- Обновление приложения — только по кнопке «Обновить» на плашке, без автоперезагрузки посреди ввода.
- Выбор темы хранится в localStorage (настройка интерфейса). Финансовые данные — в IndexedDB через Dexie (`src/db/db.ts`, схема **версии 1**).
- Схема БД v1: `accounts`, `categories`, `transactions`, `meta`. id — UUID-строки. Даты операций — строка `ГГГГ-ММ-ДД` по местному времени. Суммы — копейки, всегда > 0; знак задаёт тип (expense / income / transfer).
- Стартовые категории имеют постоянные id `seed-expense-1…12`, `seed-income-1…4`.
- Все изменения данных — через `src/db/repo.ts` (проверки: сумма > 0, категория подходит к типу, перевод не на тот же счёт и т. п.).
- Объединение категорий (`mergeCategories`) сейчас переносит операции; на этапах 3, 4, 7 туда нужно добавить бюджеты, подписки и правила импорта.
- При старте приложение просит браузер о «постоянном хранилище» (`navigator.storage.persist`), чтобы данные не стирались при нехватке места.
- Публикация: GitHub Actions на каждую отправку в `main`; если тесты не прошли — публикации нет.
- `npm audit` показывает 4 moderate-предупреждения в инструментах сборки PWA (workbox → glob). В приложение не попадают; `npm audit fix --force` не запускать — он откатывает vite-plugin-pwa.
- В новых Chrome `window.scrollTo` возвращает Promise — эффекты React писать с фигурными скобками, без неявного возврата.
