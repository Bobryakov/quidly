## Принятые решения
- Название: Quidly.
- Копилки ведутся отдельно от счетов.
- Геймификация: серия дней + 5 бейджей (см. SPEC, раздел 10).
- Забытый PIN: сброс только с удалением данных, затем восстановление из бэкапа.
- Перенос остатка бюджета включён + карточка «Итоги месяца» (SPEC, раздел 5.1).
- Быстрый ввод: счёт по умолчанию — последний использованный (17.11.2026).
- Первый запуск: экран знакомства «Сколько у вас сейчас денег?» с готовыми «Карта» и «Наличные» (17.11.2026).
- Бюджеты: месяц — календарный, с 1-го числа; общий лимит = сумма категорий по умолчанию, можно вписать свой; «Отправить в копилку» в «Итогах месяца» — на этапе 5 (17.11.2026).
- Подписки: напоминать за 3 дня (можно 1 / 3 / 7); пропущенные списания — спрашивать про каждое по очереди (17.11.2026).
- Копилки: на главной «в копилках X · свободно Y»; срок цели необязательный (17.11.2026).

### Технические решения
- Адреса экранов через `#` (`/quidly/#/settings`) — чтобы GitHub Pages не выдавал «страница не найдена» при обновлении.
- Обновление приложения — только по кнопке «Обновить» на плашке, без автоперезагрузки посреди ввода.
- Выбор темы хранится в localStorage (настройка интерфейса). Финансовые данные — в IndexedDB через Dexie (`src/db/db.ts`, схема **версии 4**).
- Схема БД v1: `accounts`, `categories`, `transactions`, `meta`. v2 (этап 3): + `budgets` (лимит с месяца `fromMonth`, `limit: null` — снят; общий — `categoryId = 'total'`), + `closings` (итоги месяца: решения, переносы, покрытия). У категории необязательное поле `budgetRollover` (нет = переносить). v3 (этап 4): + `subscriptions` (nextDate, anchorDay — «число месяца» для 31-го, paused), у операций необязательное `subscriptionId` + индекс. v4 (этап 5): + `goals` (target, deadline?, achievedAt), + `goalMoves` (amount со знаком, source manual|closing). В `CloseAction` добавлен вариант `goal`, в `MonthClosing` — `toGoals`. Переходы v1 → v4, v2 → v4, v3 → v4 покрыты тестами. id — UUID-строки. Даты операций — строка `ГГГГ-ММ-ДД` по местному времени. Суммы — копейки, всегда > 0; знак задаёт тип (expense / income / transfer).
- Стартовые категории имеют постоянные id `seed-expense-1…12`, `seed-income-1…4`.
- Все изменения данных — через `src/db/repo.ts` (проверки: сумма > 0, категория подходит к типу, перевод не на тот же счёт и т. п.).
- Объединение категорий (`mergeCategories`) переносит операции, бюджеты (если у получателя нет своего) и подписки; на этапе 7 туда нужно добавить правила импорта.
- Подписки: расчёты — `src/lib/subscriptions.ts`; «Проведено» / «Пропустить» / отмена — `markSubscriptionPaid` / `skipSubscriptionCharge` / `undoSubscriptionCharge` в `repo.ts`. Сопоставление с импортированными операциями — на этапе 7 (по `subscriptionId`).
- Копилки: расчёты — `src/lib/goals.ts`; пополнение/снятие — `addGoalMove` (не даёт уйти в минус, ставит `achievedAt` при первом достижении), отмена — `deleteGoalMove`. Конфетти — `celebrate()` в `src/lib/store.ts` + `Confetti.tsx`.
- `closeBudgetMonth` выполняется одной транзакцией: записывает итоги и пополняет копилки; если выбранную копилку удалили — остаток переносится.
- Предупреждение о бюджете после траты — общий помощник `withBudgetWarning` (`src/db/budgetWatch.ts`), используется и в быстром вводе, и в «Проведено».
- Расчёты бюджета — чистые функции в `src/lib/budget.ts`. Перенос в текущий месяц: из `closings` прошлого месяца, а если он не закрыт — предварительный по умолчанию. При запуске `autoCloseMonths` закрывает по умолчанию все месяцы старше прошлого и прошлый — с 8-го числа.
- Предупреждения 80% / превышение показываются в плашке после записи траты, один раз при переходе порога.
- Номер открытия панели «+» — счётчик, а не время (иначе два быстрых открытия могли совпасть и форма не очищалась).
- При старте приложение просит браузер о «постоянном хранилище» (`navigator.storage.persist`), чтобы данные не стирались при нехватке места.
- Публикация: GitHub Actions на каждую отправку в `main`; если тесты не прошли — публикации нет.
- `npm audit` показывает 4 moderate-предупреждения в инструментах сборки PWA (workbox → glob). В приложение не попадают; `npm audit fix --force` не запускать — он откатывает vite-plugin-pwa.
- В новых Chrome `window.scrollTo` возвращает Promise — эффекты React писать с фигурными скобками, без неявного возврата.
