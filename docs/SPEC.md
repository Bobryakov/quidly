# Quidly — описание функций

Название приложения: **Quidly** (на иконке и в заголовке).

Личный учёт финансов. Mobile-first, интерфейс на русском. Все данные хранятся только на устройстве.
Общие ограничения (валюта, форматы, хранение, PIN) — в `CLAUDE.md`.

Пометка **[уточнить]** — решение по умолчанию, которое ждёт подтверждения владельца.

---

## 1. Счета

- Несколько счетов разных типов: карта, наличные, вклад.
- У счёта: название, тип, эмодзи/цвет, начальный баланс, признак «архивный».
- Баланс счёта = начальный баланс + доходы − расходы ± переводы.
- **Переводы** между своими счетами — отдельный тип операции: уменьшают баланс одного счёта и увеличивают другой, **не считаются ни расходом, ни доходом** и не попадают в бюджеты и аналитику трат.
- На главной — общий баланс по всем неархивным счетам.
- **Первый запуск** — короткое знакомство «Сколько у вас сейчас денег?»: готовые счета «Карта» и «Наличные», можно вписать остатки, добавить или убрать счета (решено 17.11.2026).
- В настройках у счёта правится «Сейчас на счёте»; приложение само пересчитывает начальный баланс.
- Счёт с операциями нельзя удалить — только убрать в архив.

## 2. Быстрый ввод (главная фишка)

Цель: от открытия приложения до сохранённой траты — **не больше 2–3 тапов**.

- Большая кнопка «+» на главной (и доступна с любого основного экрана).
- После нажатия сразу открывается цифровая клавиатура (своя, крупная; запятая для копеек).
- Под клавиатурой — сетка категорий с эмодзи. Наверху — недавние и частые категории.
- Тап по категории сохраняет операцию (сценарий: «+» → сумма → категория = готово).
- Переключатель **расход / доход / перевод** (по умолчанию — расход). Для перевода вместо категорий — выбор счетов «Откуда» и «Куда» и кнопка «Перевести».
- Необязательные поля: комментарий, дата (по умолчанию «сегодня»), счёт (по умолчанию — последний использованный; решено 17.11.2026).
- Операцию можно отредактировать и удалить. После удаления — всплывающая плашка «Отменить» на несколько секунд.

## 3. Категории

- Стартовый набор с эмодзи и цветами:
  - расходы: 🛒 Продукты, ☕ Кафе, 🚌 Транспорт, 🏠 Дом, 💊 Здоровье, 📺 Подписки, 🎉 Развлечения, 👕 Одежда, 🎁 Подарки, 📱 Связь, 📚 Образование, 💸 Прочее;
  - доходы: 💰 Зарплата, 🎁 Подарки (доход), 📈 Проценты, 💵 Прочие доходы.
- Можно добавлять, переименовывать, менять эмодзи и цвет.
- **Объединение** категорий: все операции, бюджеты, правила импорта и подписки переносятся в выбранную категорию, исходная удаляется.
- Удаление категории с операциями — только через перенос операций в другую категорию.

## 4. Импорт банковских выписок

Банки: **Т-Банк, Сбер, Альфа-Банк**. Сделано (этап 7, 17.11.2026): **Сбер (PDF)** и **универсальный CSV/Excel**. Т-Банк и Альфа — после того, как появятся реальные примеры в `samples/`.

### 4.1. Подготовка (до написания парсеров)
- Владелец кладёт реальные выписки в папку `samples/` (инструкция `docs/guides/08-vypiski-dlya-importa.md`). Папка в `.gitignore` — реальные файлы не попадают на GitHub; для тестов — выдуманные файлы того же устройства.
- Форматы **не придумываются**: парсер пишется только по реальному примеру.

### 4.2. Форматы
- **Сбер, PDF «Выписка по платёжному счёту»** (СберБанк Онлайн): строка операции — дата, время, категория банка, сумма (поступления со знаком «+»), остаток; следующая строка — дата обработки, код авторизации, описание (может продолжаться на следующих строках; «В сумму операции включена комиссия … руб.» выделяется как комиссия). Колонки различаются по координатам на странице; чтение — pdf.js прямо в браузере.
- Сверка Сбера: сумма прочитанных поступлений и списаний должна совпасть с «Пополнение» и «Списание» в шапке — иначе предупреждение.
- **Универсальный импорт** CSV/XLSX: колонки угадываются по названиям, можно поправить (дата, описание, сумма со знаком **или** две колонки «поступления / списания», категория банка, MCC), строка заголовков, переключатель «расходы без минуса». Кодировка CSV — UTF-8 или Windows-1251 (определяется сама).
- Пресеты Т-Банка и Альфа-Банка — по реальным примерам (позже).

### 4.3. Предпросмотр перед сохранением
- Список операций по дням с галочками; сводка: к импорту / переводов на свои счета / уже импортировано / похоже на ваши записи / взаимозачёт возвратов.
- Выбор счёта для импорта (для Сбера по умолчанию — счёт со словом «Сбер» в названии).
- Категорию можно поправить тапом — правка применяется ко всем покупкам этого продавца и запоминается правилом.
- **Переводы между своими счетами** (решено 17.11.2026): предлагаются как перевод, если в Quidly есть подходящий счёт — «Наличные» для выдачи/внесения наличных, счёт с названием банка для «Перевод в T-Bank» и т. п. (SBOL — переводы внутри Сбера — на второй счёт со словом «Сбер»). Можно выбрать другой счёт или сказать «это расход/доход»; у расходов-переводов есть подсказка «⇄ себе?».
- Комиссия за снятие наличных записывается отдельной тратой («Прочее»), перевод на «Наличные» — без комиссии.
- **Возвраты** (решено 17.11.2026): если в той же выписке есть покупка у того же продавца на ту же сумму — обе не импортируются (взаимозачёт); иначе возврат — доход «Прочие доходы».
- **Выравнивание остатка**: если в выписке есть остаток на конец периода (Сбер) и баланс счёта в Quidly на эту дату после импорта с ним не совпадает — предлагается «Выровнять остаток по выписке» (меняется начальный остаток счёта; операции после даты выписки не трогаются).

### 4.4. Дедупликация
- У каждой импортированной операции есть метка (банк, счёт, дата, время, направление, сумма, код авторизации, продавец + номер повтора). Повторный импорт той же выписки помечает всё «уже импортировано» и ничего не задваивает (даже если вручную поставить галочки).
- Операции, внесённые вручную (решено 17.11.2026): совпадение по счёту, типу, сумме и дате ±1 день → «похоже на вашу запись», галочка **снята**, можно поставить. Одна ручная запись совпадает максимум с одной строкой.
- Подписки: списание с той же суммой ±3 дня от ожидаемой даты считается проведённым — операция связывается с подпиской, дата следующего списания сдвигается.

### 4.5. Автокатегоризация
- Порядок: правило пользователя → категория банка → MCC-код → «Прочее» / «Прочие доходы».
- Правила — по «ключу продавца» (без номеров магазинов и городов: «PYATEROCHKA 8813 MOSCOW RUS» → «PYATEROCHKA»).
- Управление правилами: «Настройки → Правила импорта» (просмотр, правка, удаление, добавление).

## 5. Бюджеты

- Месяц бюджета — календарный, с 1-го числа (решено 17.11.2026).
- Месячный лимит на категорию и общий месячный лимит.
- Общий лимит по умолчанию = сумма лимитов категорий (с переносами); можно вписать свой — тогда в него входят все расходы месяца, даже по категориям без лимита (решено 17.11.2026).
- Новый лимит действует с текущего месяца; прошлые месяцы не пересчитываются.
- Цветной прогресс-бар: зелёный (< 80%), жёлтый (80–100%), красный (> 100%).
- Предупреждение (внутри приложения) при достижении 80% и при превышении: в плашке после записи траты — один раз при переходе порога.

### 5.1. Перенос остатка и «Итоги месяца»
- Перенос остатка включён: неистраченный остаток категории переходит в лимит следующего месяца («Лимит 10 000 ₽ + 1 200 ₽ с прошлого месяца»).
- Перенос можно выключить для отдельной категории (например, для «Подарков» он полезен, для «Кафе» — нет).
- В начале нового месяца на главной появляется карточка **«Итоги месяца»**. В ней остатки и перерасходы по категориям и варианты, что сделать с остатком:
  - 🔁 **Перенести** в ту же категорию (по умолчанию);
  - 🐷 **Отправить в копилку** — выбрать цель, сумма записывается как её пополнение последним днём закрытого месяца, с комментарием «Остаток «Кафе» за октябрь» (сделано на этапе 5);
  - 🩹 **Покрыть перерасход** — остаток одной категории закрывает минус в другой (например, сэкономили на кафе — покрыли перерасход в транспорте);
  - 🧹 **Обнулить** — начать месяц с чистого лимита.
- Можно выбрать одно действие для всех категорий («Перенести всё», «Всё в копилку») или настроить по каждой.
- Если ничего не выбрано, через 7 дней применяется действие по умолчанию — перенос.
- Перерасход по умолчанию **не переносится** минусом на следующий месяц. В настройках можно включить «Переносить перерасход».
- Если несколько категорий покрывают один перерасход, первой гасит та, что выше в списке категорий; остаток после покрытия переносится (или обнуляется, если перенос для категории выключен).
- Итоги закрытого месяца «замораживаются»: если позже исправить операцию прошлого месяца, перенос уже не пересчитывается.
- Расчёт переноса, покрытия и итогов покрывается тестами.

## 6. Подписки и регулярные платежи

- Поля: название, сумма, периодичность (неделя / месяц / квартал / год), дата следующего списания, счёт, категория.
- Список ближайших списаний и сумма подписок в пересчёте на месяц.
- При открытии приложения — баннер «Скоро спишется» (за N дней: 1 / 3 / 7, по умолчанию 3, меняется на экране «Подписки» — решено 17.11.2026) с кнопкой «Проведено» — одним тапом создаёт операцию и сдвигает дату следующего списания. После «Проведено» — плашка с «Отменить».
- Трата записывается датой списания (если отметили заранее — сегодняшней датой), с комментарием = название подписки.
- Пропущенные списания (приложение долго не открывали): по каждому спрашиваем «Списалось ДД.ММ.ГГГГ?» — «Проведено» или «Пропустить», по очереди, начиная с самого раннего (решено 17.11.2026).
- Подписка «на 31-е» в коротких месяцах списывается в последний день месяца, потом снова 31-го.
- Подписку можно поставить на паузу (не напоминать и не считать в сумму за месяц) и удалить (записанные траты остаются).
- Нельзя удалить счёт или категорию, к которым привязана подписка; при объединении категорий подписки переходят в новую категорию.
- Сопоставление с импортированными операциями: если в выписке найдено списание с похожей суммой и описанием рядом с датой — подписка считается проведённой, дубль не создаётся.

## 7. Цели (копилки)

- Поля: название, эмодзи, цвет, целевая сумма, срок (**необязательный** — решено 17.11.2026).
- Пополнение и снятие (история движений).
- Подсказка: «Чтобы успеть к сроку, откладывай X ₽ в месяц» — остаток делится на число месяцев, считая текущий и месяц срока, округляется вверх до рубля. Без срока — просто «Осталось X ₽».
- Снять больше, чем лежит в копилке, нельзя. После пополнения/снятия — «Отменить».
- Конфетти при достижении цели (один раз — в момент, когда цель впервые достигнута). Достигнутые цели — в отдельном списке «Достигнуты 🎉».
- Копилки ведутся **отдельно от счетов**: пополнение и снятие не меняют балансы счетов и не считаются расходом или доходом. Это виртуальный учёт отложенных денег.
- На главной под общим балансом: «🐷 в копилках X ₽ · свободно Y ₽» (решено 17.11.2026).
- Удаление копилки удаляет её историю; деньги на счетах не меняются.

## 8. Аналитика

- Период: **месяц** (листается стрелками), **3 месяца** (включая текущий), **год** (текущий календарный).
- **Траты по категориям** за выбранный период: кольцевая диаграмма + список с суммами и процентами; по тапу — операции категории (экран «Операции» с фильтром).
- **Динамика по месяцам**: доходы и расходы за 6 месяцев (столбики), сравнение с прошлым месяцем. Для текущего (незаконченного) месяца сравниваются те же дни: «За 17 дней ноября потрачено на X% меньше, чем за те же дни прошлого месяца».
- **Прогноз** (текущий месяц): «При таком темпе потратишь X ₽ за месяц» = потрачено с 1-го по сегодня ÷ прошедшие дни × дней в месяце; «Можно тратить Y ₽ в день» = (общий бюджет − потрачено) ÷ оставшиеся дни, считая сегодня, вниз до рубля; без бюджета — подсказка задать бюджет.
- **Календарь-тепловая карта** трат по дням (неделя с понедельника, 4 оттенка от «мало» до «самый дорогой день»); по тапу — операции дня.
- Переводы между своими счетами в аналитику трат не входят.

## 9. Защита и данные

### 9.1. PIN и биометрия
- PIN-код 4–6 цифр, хранится только как хеш (PBKDF2 + соль). Включение: «придумайте» → «повторите»; смена и выключение — только с текущим PIN (или отпечатком).
- Автоблокировка, когда приложение уходит в фон, с настраиваемым таймаутом (сразу / 1 / 5 / 15 минут), **по умолчанию — через 1 минуту** (решено 21.11.2026). При каждом новом запуске PIN спрашивается всегда.
- Вход по отпечатку или лицу через WebAuthn — **сразу на этапе 8** (решено 21.11.2026), если телефон поддерживает. После включения PIN приложение само предлагает «Входить по отпечатку?». PIN остаётся запасным способом.
- После 5 неверных PIN подряд — пауза 30 секунд, после 10 — 5 минут, дальше — 15 минут на каждые 5 ошибок.
- Важно для пользователя: **PIN — это замок экрана, а не шифрование.** Он не даёт открыть приложение постороннему, но сами данные на устройстве не зашифрованы. В интерфейсе это коротко объясняется в настройках PIN.
- Если PIN забыт: сбросить PIN можно только вместе с удалением всех данных (два шага: предупреждение с датой последней копии → ввести слово «УДАЛИТЬ»). После этого данные восстанавливаются из бэкапа — кнопка «Восстановить» есть прямо на экране знакомства.

### 9.2. Экспорт
- Экспорт операций за выбранный период (этот месяц / прошлый / этот год / всё время / свои даты) в .xlsx и CSV.
- Колонки: Дата, Тип, Сумма (расход — с минусом), Счёт, Куда (для переводов), Категория, Комментарий.
- CSV — для русского Excel: разделитель «;», дробная часть через запятую, даты ДД.ММ.ГГГГ. Excel — настоящие даты и числа.

### 9.3. Бэкап и восстановление
- Полный бэкап всех данных в JSON-файл (с версией схемы БД). **Пароль — по желанию** (решено 21.11.2026): с паролем файл зашифрован, без пароля его не открыть никому, восстановить пароль нельзя.
- В копию не входят настройки самого телефона: PIN, отпечаток, автоблокировка, дата последней копии.
- Восстановление: проверка файла (формат, версия, целостность) → «что в копии» (дата, счета, операции, копилки, подписки) → подтверждение «текущие данные будут заменены» (с кнопкой «Сначала сохранить копию текущих данных») → восстановление. Если что-то пошло не так, текущие данные не меняются.
- Бэкапы старых версий схемы восстанавливаются через миграции.
- Напоминание о бэкапе раз в неделю (на главной; «Завтра» — отложить на сутки). Если копий не было — через неделю после начала учёта. В настройках — дата последнего бэкапа.
- Телефон владельца — Android: файл сохраняется в «Загрузки», оттуда его можно отправить в Google Диск.

## 10. Геймификация (лёгкая)

Утверждённый набор (не перегружать):
- 🔥 **Серия дней учёта** — дни подряд, когда была внесена хотя бы одна операция (или нажато «Сегодня трат не было»).
- Бейджи:
  - 🌱 «Первый шаг» — первая операция;
  - 📅 «Неделя без пропусков» — серия 7 дней;
  - 🎯 «Месяц в рамках бюджета» — общий бюджет не превышен;
  - 🐷 «Копилка полна» — первая достигнутая цель;
  - 💾 «Надёжный» — 4 недели подряд с бэкапом.
- Без очков, уровней и рейтингов.

## Экраны

Нижнее меню: **Главная · Операции · Аналитика · Цели · Настройки**, кнопка «+» всегда под рукой.

- **Главная**: общий баланс, прогресс бюджета месяца, ближайшие подписки, последние операции, баннеры («Скоро спишется», напоминание о бэкапе, предупреждения бюджета).
- **Операции**: список по дням, поиск по описанию/комментарию, фильтры (период, счёт, категория, тип). Фильтры хранятся в адресе экрана — аналитика открывает операции категории или дня.
- **Аналитика**: см. раздел 8.
- **Цели**: список копилок с прогрессом.
- **Настройки**: счета, категории, бюджеты, подписки, правила импорта, импорт выписок, PIN и автоблокировка, тема (светлая / тёмная / как в системе), экспорт, бэкап и восстановление.

Пустые экраны — дружелюбные, с эмодзи и подсказкой, что сделать (например: «Пока пусто. Нажми ➕, чтобы добавить первую трату»).

## Дизайн

Яркий, игровой: цветные карточки, эмодзи категорий, анимации (Framer Motion). Суммы крупные и хорошо читаются. Светлая и тёмная тема.

## Публикация

- GitHub: аккаунт `Bobryakov`, репозиторий `quidly` (публичный — этого требует бесплатный GitHub Pages; данные пользователя в репозиторий не попадают).
- Адрес приложения: https://bobryakov.github.io/quidly/
- Публикация автоматическая через GitHub Actions при каждом обновлении основной ветки.

## Форматы

- Деньги: `1 234,56 ₽` (неразрывный пробел между разрядами, запятая для копеек).
- Даты: `ДД.ММ.ГГГГ`. Неделя начинается с понедельника.
- Суммы хранятся в копейках (целые числа), чтобы не было ошибок округления.
