# Этап 1: запуск на ноутбуке и публикация на GitHub

Время: около 15 минут. Компьютер: Windows, PowerShell.

Файлы приложения я уже положил в папку `quidly`. Осталось: посмотреть приложение на ноутбуке, создать репозиторий на GitHub и отправить туда код. После этого приложение само опубликуется по адресу https://bobryakov.github.io/quidly/

> **Репозиторий** — папка проекта на сайте GitHub, где хранится код и вся история изменений.

---

## Шаг 1. Откройте PowerShell в папке проекта

«Пуск» → `PowerShell` → Enter. Затем:

```
cd $HOME\Projects\quidly
```

✅ **Должны увидеть:** строку приглашения, которая заканчивается на `\Projects\quidly>`

---

## Шаг 2. Положите файл автопубликации на место

Файл с настройками автопубликации должен лежать в служебной папке `.github\workflows`. Мне запись туда закрыта, поэтому я положил его в папку `scripts` — переложите одной командой:

```
New-Item -ItemType Directory -Force .github\workflows | Out-Null; Move-Item scripts\deploy.yml .github\workflows\deploy.yml
```

Проверьте:

```
Test-Path .github\workflows\deploy.yml
```

✅ **Должны увидеть:** `True`

---

## Шаг 3. Установите пакеты

Пакеты — готовые библиотеки, из которых собирается приложение. Ставятся один раз (и после крупных обновлений).

```
npm install
```

Займёт 1–2 минуты.

✅ **Должны увидеть:** в конце строку вида `added 434 packages in 40s`.

ℹ️ Жёлтая строка `npm warn deprecated glob@...` — просто предупреждение, не ошибка.

ℹ️ Может появиться `4 moderate severity vulnerabilities` — это нормально. Предупреждение касается инструмента сборки, а не самого приложения, и к вашим данным отношения не имеет. **Не запускайте** `npm audit fix --force` — эта команда сломает сборку.

---

## Шаг 4. Прогоните тесты

Тесты — небольшие автоматические проверки: правильно ли пишутся суммы и даты, работает ли меню.

```
npm test
```

✅ **Должны увидеть:** `Tests  12 passed (12)` (зелёным).

---

## Шаг 5. Посмотрите приложение на ноутбуке

```
npm run dev
```

✅ **Должны увидеть:** строку `Local: http://localhost:5173/quidly/`

Откройте этот адрес в браузере (зажмите Ctrl и кликните по ссылке). Проверьте:

- внизу меню из 5 разделов, переключаются;
- круглая кнопка «+» открывает панель «Быстрый ввод скоро появится»;
- «Настройки» → «Тёмная» — экран темнеет.

Чтобы остановить: вернитесь в PowerShell и нажмите **Ctrl+C** (если спросит — `Y` и Enter).

---

## Шаг 6. Представьтесь программе Git (один раз)

Git подписывает каждое сохранение изменений именем и почтой. Проверьте, задано ли имя:

```
git config --global user.name
```

Если команда ничего не вывела — задайте имя и почту (почту — ту же, что в аккаунте GitHub):

```
git config --global user.name "Bobryakov"
git config --global user.email "ваша-почта@example.com"
```

✅ **Должны увидеть:** ничего — это значит, что всё сохранилось.

---

## Шаг 7. Создайте репозиторий на GitHub

1. Откройте https://github.com/new (войдите в аккаунт `Bobryakov`, если попросит).
2. **Repository name:** `quidly`
3. Выберите **Public** (бесплатная публикация работает только для открытых репозиториев; ваши финансовые данные туда не попадают — они живут только в телефоне).
4. Ничего не добавляйте: **не** ставьте галочки README, .gitignore, license.
5. Нажмите **Create repository**.

✅ **Должны увидеть:** страницу с заголовком «Quick setup» и адресом `https://github.com/Bobryakov/quidly.git`.

---

## Шаг 8. Включите публикацию (GitHub Pages)

1. В репозитории откройте вкладку **Settings** (шестерёнка вверху).
2. Слева — **Pages**.
3. В блоке **Build and deployment** → **Source** выберите **GitHub Actions**.

✅ **Должны увидеть:** под выбором — надпись про workflow (сохранять ничего не нужно, выбор применяется сразу).

> **GitHub Actions** — «робот» GitHub: после каждой отправки кода он сам прогоняет тесты, собирает приложение и выкладывает его на сайт.

---

## Шаг 9. Отправьте код на GitHub

В PowerShell (в папке `quidly`) по очереди:

```
git init -b main
```
✅ `Initialized empty Git repository in ...`

```
git add .
```
✅ Ничего или предупреждения про `LF`/`CRLF` — это нормально.

```
git commit -m "Этап 1: каркас, PWA, автопубликация"
```
✅ Строка вида `[main (root-commit) 1a2b3c4] Этап 1: ...` и `39 files changed`.

```
git remote add origin https://github.com/Bobryakov/quidly.git
```
✅ Ничего.

```
git push -u origin main
```
При первой отправке откроется окно входа в GitHub — нажмите **Sign in with your browser** и подтвердите.

✅ **Должны увидеть:** в конце `branch 'main' set up to track 'origin/main'`.

---

## Шаг 10. Дождитесь публикации и откройте приложение

1. В репозитории откройте вкладку **Actions**.
2. Там появится запуск «Публикация на GitHub Pages». Через 1–3 минуты рядом с ним будет **зелёная галочка** ✅.
3. Откройте https://bobryakov.github.io/quidly/

✅ **Должны увидеть:** то же приложение, что и на ноутбуке.

---

## Шаг 11. Установите на телефон

- **Android (Chrome):** откройте адрес → меню ⋮ → **Установить приложение** (или «Добавить на главный экран»).
- **iPhone (Safari):** откройте адрес → кнопка «Поделиться» → **На экран «Домой»**.

✅ **Должны увидеть:** иконку Quidly (фиолетово-розовая, с буквой Q) на рабочем столе телефона. Приложение открывается без адресной строки и работает даже без интернета.

---

## Если что-то пошло не так

| Проблема | Что делать |
|---|---|
| В Actions красный крестик ❌ | Проверьте шаг 8 (Source = GitHub Actions) и шаг 2 (файл `deploy.yml` на месте). Затем Actions → «Публикация на GitHub Pages» → кнопка **Run workflow** → **Run workflow**. Не помогло — пришлите скриншот красного шага. |
| `git push` пишет `rejected` или `remote contains work` | При создании репозитория была отмечена галочка README. Напишите мне — подскажу, как исправить. |
| `npm` пишет «выполнение сценариев отключено» | Выполните `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned`, ответьте `Y`, повторите команду. |
| Сайт открывается, но показывает старую версию | Закройте вкладку и откройте снова: сверху появится плашка «Вышла новая версия» → **Обновить**. |
| Любая другая ошибка | Скопируйте текст ошибки или сделайте скриншот и пришлите мне. |
